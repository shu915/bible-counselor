# 安全(命に関わる相談・ハラスメント・出さない箇所)

> **この版(LLM だけ)での変更**: 参照元(RAG 版)にあった「出さない箇所を、DB の検索の条件で、コードで外す」仕組みは、**ない**(DB がない)。代わりに、①プロンプトで、責める節・死を望む節を選ばせない ②「それでも続ける」のとき、命が失われることを語る節(`LIFE_LOSS_WORDS`)を含む箇所を、コードで外す。以下の「出さない箇所」の節は、**参照元の記録**で、どの箇所が問題だったかの、参考として残す(プロンプトの規則の根拠)。
> 命の危険の入力を、AI を呼ぶ前に、キーワードで止める仕組み(`src/lib/crisis.ts`)は、そのままで、変わらない。


悩み・弱音・懺悔を受け付けるので、「死にたい」と書かれる相談は、現実に来る。**未実装。画面と API ルートを作るときに、最初から組み込む**(後付けにしない)。

## 1. 命の危険を示す入力(決定的に、AI の前で止める)

- 入力を AI(OpenRouter)に送る**前に**、危機を示す語を、単純なキーワードで検出する。AI の成否・回数制限・検索の失敗に、依存させない
  - 語の案(誤検出は許す。見逃しを減らす): 死にたい、消えたい、いなくなりたい、生きていたくない、生きるのがつらい、自殺、自傷、終わりにしたい、楽になりたい、など(表記ゆれは、`normalize` してから)
- 検出したら、**固定の画面**を出す。AI を呼ばない・聖句の検索もしない・回数に数えない
  - 内容: 気持ちを受け止める短い固定文 → 相談窓口(下記) → 「いま危険なときは、119・110 へ」
  - 聖句の引用は、既定では出さない(下記 3)
- **検出は、サーバー側で、AI を呼ぶ前に、すべての AI 呼び出し(書き換えも含む)の前で行う**(長さの上限の検査の後でよい)
- **見逃しは、必ず出る。見逃しを減らすことより、見逃したときにも安全な設計にする**
  - 表記の幅を持たせる: NFKC に加えて、ひらがな・カタカナ・漢字(「しにたい」「シニタイ」「死にたい」)、くだけた書き方、自傷や手段に関する語。誤検知は許す方針なので、広めでよい
  - 入れる語のリストは、人が作る。**テストの例文(検出すべき/すべきでない)として固定**し、リストを変えたときに、挙動が分かるようにする
  - 語は、語幹で止める(「死にた」で、「死にたくなる」「死にたかった」を拾う)。**漢字の語は、ひらがな版も持つ**(正規化で効くのは、カタカナ → ひらがなだけ)。ゼロ幅スペースなどの書式文字は、取り除いてから比べる
  - 「死んでしま」を語幹にすると、「大切な人が死んでしまった」(死別の相談)を誤検知する。「死んでしまいたい」「死んでしまえ」のように、**先を足した形**で拾う(「しまった」は避ける)
  - 単独では広すぎる語(「しんどい」「飛び込み」)は、入れない(「仕事がしんどい」「飛び込み営業」を誤検知するため)。「生きるのがしんどい」「電車に飛び込みたい」のように、文脈つきで入れる
  - 「死にそう」は、「祖母が死にそうだ」(看取りの相談)や慣用句も検出する。許容する(固定画面と、「それでも続ける」が出るだけ)。**固定画面の文面は、「命の危険を感じている」と決めつけず、「つらいときの案内」として読める言い方にする**
  - 見逃しても害を減らす: ①AI が命に関わる内容と判断したときも、同じ固定の画面にする(キーワードの見逃しの保険) ②通常の出力から、死を望む箇所を外す(3 の「出さない箇所」)
  - 追加の防御(主にしない): 生成の LLM に、危機のフラグを返させて、立てば結果を固定画面に差し替える案がある。生成は、そもそも呼ぶので、追加の呼び出しは要らない。ただし**非決定的なので、主たる防御にしない**
  - **誤検知で、人を締め出さない**: 「死にたいくらい恥ずかしい」のような文でも、固定画面だけで終わらず、「それでも相談を続ける」の選択肢を用意する
- 入力は保存しない・ログに出さない(検出に使うだけ)。検出の有無も、記録しない
- 相談窓口は、**命の危険を感じる言葉を書いたときの画面にだけ**出す(通常の画面には、出さない。検索サービスが、「自殺」と入れたときだけ窓口を出すのと同じ形。ユーザーの判断、2026-11-19)
- **窓口の名前と電話番号は、公開前に、公式の最新の情報を、人が確認して入れる。Claude は、番号を断定して書かない**(要確認: よりそいホットライン、いのちの電話、こころの健康相談統一ダイヤル など)

## 2. 聖書の「死にたい」への扱い(2026-11-18 の確認)

- 聖書には、死を願う人が出てくる(エリヤ: 列王紀上 19:4。ヨブ: ヨブ記 3。エレミヤ: エレミヤ書 20:14-18)。エリヤには、神が責めず、食べさせて眠らせる(列王紀上 19:5-8)。詩篇 34:18(主は心の砕けた者に近い)も、寄り添いの言葉になりうる
- **ただし、アプリの通常の「3件の引用」には、死を望む箇所(ヨブ 3 など)を、出さない**。人の判定で、嘆き 3 つ + 最後に死を望む箇所は、悲嘆の相談で、最悪の並びだった(q05 の B)
- **命の危険の画面には、初回の公開では、聖句を出さない**(外部レビューの指摘)。最も傷つきやすい人に、宗教の言葉が「説得」や「はぐらかし」に感じられる危険がある。受け止める短い固定文と、窓口だけにする。候補にしていた列王紀上 19 章の段落は、「命を取ってください」の節(4 節)を含みうる
  - あとで足すなら、専門家の意見を聞いたうえで、人が決める(列王紀上 19:5-8 の「食べて、眠る」、詩篇 34:18 は、そのときの候補)。AI には選ばせない。この判断は、Claude や開発者の専門の外
- 「聖書に答えがある」と、議論や説得の形では、出さない(「自殺は罪だ」のような叱責・説教は、しない)

## 3. 出さない箇所(どんな悩みでも出さない)

ユーザー(人)の判定で決めたもの。**コードで、候補から外す**(LLM の判断に任せない)。

| 段落 | 理由 |
|---|---|
| Isa.40.27-31 | 「主を待ち望めば力を得る」という一律の約束で、神頼み |
| Isa.41.8-16 | 同じ(神がなんとかしてくれる) |
| Job.3.11-19 / Job.3.20-26 | 死を望む箇所 |
| 1Pet.2.18-25 | 不当な扱いに耐えろ(奴隷への服従)。ハラスメントに害 |
| Jas.1.5-8 | 疑う者を責める節を含む |

(段落単位なので粗い。追加・削除は、人が1件ずつ決める。**悩みで良し悪しが変わるもの(伝道 4:6 など)は、このリストに入れない**。それは、選択のプロンプトと、解説の生成で扱う)

実装のときの注意:
- **除外は、取る前に行う**: 上位 15 件を取った後で外すと、件数が減る。除外した集合から、上位 15 件を取る。補う処理(`fillSelection`)の候補も、同じ除外済みの集合にする
- **禁止リストの全 id が、実データに実在することを、テストで確認する**(1 行)。`bible:convert` の仕様が変わって id が変わると、静かに効かなくなるため
- **マタイ 11:28-30 の降格は、「固定の係数による、静的な降格」**(段落ごとの、あらかじめ決めた順位の重み。**相談をまたいで回数を数えない**: 状態を保存することになり、プライバシーの方針とぶつかる)。相談の中での偏りの調整(同じ章から複数選ばない、など)は、別に、1回の相談の中だけで行う

## 3.5 実際に入力して見つかったこと(2026-11-18)

- 「しにたい」と入力して「それでも続ける」を選ぶと、**ヨブ 7:11-21(「死を選ぶ」「長く生きることを望まない」)が、最初に出た**。除外リストに、ヨブ 3 しか入れておらず、抜けていた。
  - 死を望む言い回しの段落を、DB から洗い出し(17件)、**1件ずつ本文を見て**、実際に死を望む箇所だけを除外に足した(ヨブ 7・9・10、エレミヤ 20、ヨナ 4、列王紀上 19:1-8、黙示録 9)。正規表現での一括除外は、しない(詩篇 139 の「殺してくださる」は、敵の話で、慰めの詩)
- **結論に、AI が、電話番号(よりそいホットライン 0120-…、24時間・無料)を書いていた**。番号・窓口の名前・受付時間は、人が公式の情報で確認して、固定の案内に入れる。AI が書くと、間違い・古い情報になりうる。
  - 生成のプロンプトで禁止し、さらに、**コードで、AI の文章から電話番号を取り除く**(`removePhoneNumbers`。括弧の中の番号は、括弧ごと)
- 命の危険を示す語があって「それでも続ける」を選んだときは、**生成に専用の指示**を足す(`crisisContext`): 肯定も否定もせず受け止める・死を望む言葉を勧めに読ませない・解説は短く・窓口の名前や番号は書かない・「今日、誰か1人に伝える」を一歩にする。実際の AI で 3 回試して、死を望む箇所なし・番号なし・結論は「ひとりで抱えず、すぐに話して」だった
- **他人を傷つけたい気持ち**(「ぶっ殺してやる」)は、自傷とは別。画面は止めない(大げさな言い回しの愚痴も多い)が、生成に専用の指示を足す(`harmContext`): 怒りは責めない・**「神が代わりに罰する」と読ませない**(相手への害の正当化になる)・その場を離れる・本当に危害を加えそうなら、警察などの緊急の窓口へ(番号は書かない)

## 4. 生成の規則(解説・結論)

- 信仰がなくても受け取れる言い方にする。「だから神を信じなさい」とは書かない
- 病気は、神の怒りや罰ではない(現代の考え方)。病を神の怒りと読める箇所が出たときは、解説で断る
- 命令形(〜しなさい)を、押しつけない。「古くから、こういう知恵が語られてきた」という距離で書く
- ハラスメント・暴力に近い相談で、耐え忍べを勧めない。結論に、相談窓口の固定文を添える。「ゆるせ」も強要しない(ゆるせない気持ちは自然・ゆるすことは関係を続けることではない)
- 免罪にしない(「赦された」と断言せず、現実の謝罪・償いは別のこととして添える)
- 一律の約束(必ず報われる・必ず力を得る)をしない。因果応報には、聖書の中の異論(伝道の書)にも触れる

## 5. 人物・書物の指名(2026-11-20。一般古典・聖書・リアリズム)

相談文に、人物(「孔子ならなんと言う?」)や書物(「徒然草には、なんて書いてある?」)の指名があれば、その指名を、箇所の選び方より優先する。実装は、プロンプトだけ(`src/lib/shelf-prompts.ts` の `namedSourceRule`。聖書の棚にも、`generate-counsel.ts` で足す)。コードでは検査できない。

- **優先するもの**: 指名。3つとも、その人物・書物の箇所にしてよい(「別の書物にする」「有名な3冊は多くて1つ」などの規則は、指名のときだけ外れる)
- **変わらないもの**: 安全の規則(命・暴力・欺き・耐えろを勧めない)は、指名より優先する
- **その人になりきらない**: 本人が書いた・語ったと伝わる箇所だけ。新しい台詞を作らない。出典があいまいな名言(ナポレオンなど)は選ばない
- **著作権**: 日本の没後70年。今年なら、(今年 − 71)年以前に亡くなった人だけ引く(`PUBLIC_DOMAIN_DEATH_YEAR`。年が変わると自動で進む)。切れていない人(存命・最近亡くなった人)と、没年に自信がない人は、前置き(preface)で「引用できない」と伝えて、近い主題の古典から選ぶ。外国の人は、戦時加算などで延びることがあり、AI では判断できない(自信がなければ出さない、と頼むだけ)。日本語訳の著作権は、本文を自分の言葉で書くので、問題になりにくい
- **現代の創作の台詞(ゲーム・アニメ・小説・漫画)は、引かない**。原典でなく、著作権がある。神話・伝説の人物は、その人物を描いた古典(叙事詩・伝記・騎士物語)の、実際に書かれた箇所から
- **棚の振り分け**: 範囲の外の指名は、前置きで別の棚を案内して、その棚の本から選ぶ(黙って、いつもの書物に切り替えない)
  - 一般古典: 聖書→聖書の棚、兵法・政治思想・処世術の書と軍人・政治家(ナポレオンなど)→リアリズムの棚。神話・伝承の書・叙事詩・騎士物語は、この棚で出す。アレクサンドロス大王のような、伝記で描かれる王も、この棚で出す
  - リアリズム: 一覧にない人物でも、戦略・軍事・政治・処世を幻想なしに語る系統なら範囲の中(ナポレオン・ビスマルク・諸葛亮など)。叙事詩・騎士物語・軍記物・演義は、範囲の外(一般古典を案内)
  - 聖書: 聖書の中の人物・書だけ
- **未解決**: 生きている人物は、リアリズムの範囲外として一般古典へ案内され、一般古典でも、著作権で断られる(案内先で、また断られる)

詳しい判定と理由は [eval/human-review.md](../eval/human-review.md)。
