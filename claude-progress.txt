# 進捗(Shu の本棚 / リポジトリ shu-bookshelf)

最終更新: 2026-11-20

## 経緯(詳しくは CLAUDE.md)

- Bible_RAG_Counselor(タグ `rag-final`)から、RAG を外して、LLM だけにした。DB はなし(回数制限の記録だけ Upstash Redis)
- 「Shu の本棚」にして、3つの棚: 一般古典(`/`)・聖書(`/bible`)・リアリズム(`/realism`)。処理は同じで、違うのはプロンプトと、見た目・文言

## できていること

- 3つの棚の画面(見た目・ヘッダー・文言・待ちの印)、危機の画面(窓口は、よりそいホットラインとあなたのいばしょ。公開の直前に、受付中かを見直す)
- 生成: 1回の呼び出しで、箇所・本文・解説・結論。人物・書物の指名を優先(docs/safety.md の 5)。存命の人物は引かない。著作権が切れた人だけ引く
- 回数制限: Upstash Redis(INCR/DECR)。IP ごと 5回・全体 100回/日。枠を戻すのは、402・429・503・設定の誤り・接続できない、だけ
- セキュリティヘッダー(nosniff・X-Frame-Options・frame-ancestors・Referrer-Policy・Permissions-Policy)
- 費用の実測: 1回 約 $0.02〜0.03(docs/cost.md)
- テスト 241 件、`npm run check`・`npm run build` が通る

## 作業の状況

- PR #1〜#5 は、マージ済み。ブランチ `pre-release-cleanup` に、**未コミット**の変更がある(ロックの名前・口語訳の緩和・存命の人物の規則・プレビューの削除・`inQuote` の掃除・Redis のテスト・レビューの直し・費用の計測・docs/deploy.md)
- 次: コミット → PR → マージ → デプロイ(docs/deploy.md の手順)

## デプロイ(人がやること)

1. Upstash(本家)で Redis を作る。OpenRouter で本番用のキーを作る(月の上限つき)
2. Vercel のプロジェクトを作り、環境変数を Production と Preview の両方に入れる(`OPENROUTER_API_KEY`・`RATE_LIMIT_SALT`・`UPSTASH_REDIS_REST_URL`・`UPSTASH_REDIS_REST_TOKEN`)
3. 仮のアドレスで確認 → `shelf.` の CNAME を Xserver に足す(プロキシなし)→ もう一度確認
4. 広く公開するときに、noindex を外す(`next.config.ts` と `layout.tsx`)

## 決めたこと

- コミットは、ユーザーが「コミットして」と言うまでしない。別窓でレビューした変更には、evaluator を呼ばない
- 専門家には見せない。免責は、最小限に軽くする
- 存命の人物は、どの棚でも引かない(別の棚へも案内しない)
- 聖書の本文は、口語訳の一字一句を求めない(現代の日本語でよい)
- 全体の 1 日の上限は 100 回のまま(月の上限は、デプロイのときに決める)

## 将来の課題

- 質の改善: 本文の正確さを、ときどき見る。指名の規則(なりきらない・出典の確かさ)は、プロンプトの頼みで、コードでは守れない
- 棚ごとのテストの充実、CI の action を SHA で固定、CSP の `script-src`(XSS が起きる箇所が増えたとき)

## つまずいたことのメモ(技術)

- macOS の npm は、ロックから `@rolldown/binding-*` を落とすことがある(docs/harness.md)
- ガードは、`rm -r`・`git push --delete`・`.env*` を含むコマンドなどを止める。迂回せず、人にお願いする。`&&` でつなぐと誤検知することがある
- ブランチの削除(リモート)は、人の手作業
