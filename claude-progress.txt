# 進捗(Shu の本棚 / リポジトリ shu-bookshelf)

最終更新: 2026-11-20(夜)

## 経緯(詳しくは CLAUDE.md)

- Bible_RAG_Counselor(タグ `rag-final`)から、RAG を外して、LLM だけにした。DB はなし(回数制限の記録だけ Upstash Redis)
- 「Shu の本棚」にして、3つの棚: 一般古典(`/`)・聖書(`/bible`)・リアリズム(`/realism`)。処理は同じで、違うのはプロンプトと、見た目・文言

## できていること

- 3つの棚の画面(見た目・ヘッダー・文言・待ちの印)。危機の画面(窓口は、よりそいホットラインとあなたのいばしょ)
- 生成: 1回の呼び出しで、箇所・本文・解説・結論。人物・書物の指名を優先(docs/safety.md の 5)。存命の人物は引かない。著作権が切れた人だけ引く。一般古典は、用語(トリックスター・開かれた社会など)も聞ける
- 範囲: 一般古典は、神話・近代の思想・文学・社会科学・心理学も。リアリズムは、経済学・社会科学の古典と、軍人・政治家の言行も(経済学・社会科学は、どちらの棚でも出す)
- 回数制限: Upstash Redis(INCR/DECR)。IP ごと 5回・全体 100回/日。枠を戻すのは、402・429・503・設定の誤り・接続できない、だけ
- セキュリティヘッダー、費用の実測(1回 約 $0.02〜0.03。単価は Sonnet 5.5 の公開価格で計算。使ったモデルは未確認)
- **デプロイ済み**(Vercel。`bookshelf.` のサブドメイン。Xserver の DNS に CNAME。HTTPS・HSTS 確認済み)。Redis にキーと回数だけが入り、回線ごとに別の枠で数えられることを確認した。noindex のまま(URL を知っていれば、誰でも使える)
- テスト 244 件、`npm run check`・`npm run build` が通る

## 作業の状況

- PR #1〜#8 は、マージ済み。ブランチ `update-readme` に、未コミットの変更がある(README・CLAUDE.md・docs の更新、一般古典の「古典をめくる」、`npm run counsel` の既定の棚を classics に)
- 次: コミット → PR → マージ(マージすると、Vercel が自動でデプロイする)

## 次にやること

- 聖書の「開く」を、一般古典の「めくる」に、そろえる(次のブランチ)
- 広く公開する予定はない(費用の都合。クレジットが尽きるため)。noindex は、外さない。URL は、限られた人にだけ伝える(費用の守りは、回数制限と月の上限)
- 使ったモデルを、OpenRouter の履歴で確かめて、docs/cost.md の単価を、必要なら直す

## 決めたこと

- コミットは、ユーザーが「コミットして」と言うまでしない。別窓でレビューした変更には、evaluator を呼ばない
- 専門家には見せない。免責は、最小限に軽くする
- 存命の人物は、どの棚でも引かない(別の棚へも案内しない)
- 聖書の本文は、口語訳の一字一句を求めない(現代の日本語でよい)
- 全体の 1 日の上限は 100 回のまま(月の上限は、デプロイのときに決める)

## 将来の課題

- 質の改善: 本文の正確さを、ときどき見る。指名の規則(なりきらない・出典の確かさ)は、プロンプトの頼みで、コードでは守れない
- 棚ごとのテストの充実、CI の action を SHA で固定、CSP の `script-src`(XSS が起きる箇所が増えたとき)

## つまずいたことのメモ(技術)

- macOS の npm は、ロックから `@rolldown/binding-*` を落とすことがある(docs/harness.md)
- ガードは、`rm -r`・`git push --delete`・`.env*` を含むコマンドなどを止める。迂回せず、人にお願いする。`&&` でつなぐと誤検知することがある
- ブランチの削除(リモート)は、人の手作業
